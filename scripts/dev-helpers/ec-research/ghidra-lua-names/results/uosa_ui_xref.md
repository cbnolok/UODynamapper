### Caveats

- String matching is exact: names built at run time, wide strings and substrings (`_WindowGetShowing` for `WindowGetShowing`) are not found; strings reached through data tables have no code reference.
- The UI index covers `UserInterface/Default` only; the `InterfaceCore` Lua inside the packages (which wraps the `_Name` registrations) is not included.
- Result counts come from a tokenizer, not a Lua parser: `0` is a statement call, `1` an expression; calls through UI-defined names are left out.
- Field-name matches (C -> Lua tables) are by string only: a function referencing the field names of a UI table is a candidate writer, not proof.
- Elements the Default UI never uses have no attribute list, so their handlers stay unnamed; elements sharing a handler are reported, not named.
- Texture chain confidence: every listed step is checked statically; the step from `NiSourceTexture` to `NiDX9SourceTextureData::LoadTextureFile` and `UONdlFile::FileCreateFunc` goes through renderer virtual calls and is inferred (medium), the rest are direct calls, strings or vftables (high).
